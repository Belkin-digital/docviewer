# Устройство решения

Документ описывает, как просмотрщик устроен внутри: из чего состоит, почему сделан именно так,
какие у него интерфейсы и как его эксплуатировать. Пользовательская часть — в [README.md](README.md).

## 1. Задача и границы

Инструмент решает одну задачу: **быстро ходить по документации репозитория с диска** — читать
markdown как страницу, переходить по относительным ссылкам между файлами, находить нужное
и открывать файл в родном приложении macOS (VS Code, Cursor, Obsidian, Finder).

Что он **не** делает: не редактирует файлы, не знает о git, не ходит в сеть (кроме первой докачки
библиотек разметки), не имеет пользователей и прав доступа, не рассчитан на работу вне localhost.
Единственная запись на диск — `docviewer.json` открытого репозитория (состав меню и избранное).

## 2. Ключевые решения

| Решение | Почему так |
|---------|------------|
| Ноль зависимостей, только стандартная библиотека Node | Инструмент должен запускаться на любой машине без `npm install` и переживать смену версий Node; весь сервер — один файл `server.mjs` |
| Клиент без сборки: три статических файла в `public/` | Нет шага сборки — значит нечему ломаться и нечего пересобирать после правки; правка видна по F5 |
| Библиотеки разметки лежат в `vendor/`, скачиваются один раз | После первого запуска работает без интернета; `vendor/` не версионируется, репозиторий остаётся лёгким |
| Один сервер на все репозитории, проект выбирается параметром `?project=` | Одна копия кода и один процесс вместо копии инструмента в каждом репозитории — правка кода делается в одном месте |
| Состав меню лежит в самом репозитории (`docviewer.json`) | Настройка едет вместе с проектом и версионируется вместе с ним; список проектов машины (`projects.json`) — наоборот, локальный и в `.gitignore` |
| Живое обновление через `fs.watch` + SSE | Изменение файла на диске должно быть видно сразу; SSE — односторонний поток, которого достаточно, и он проще вебсокета |
| Встроенные HTML-страницы отдаёт **второй** сервер на своём порту | Странице нужны скрипты и `localStorage`, то есть свой origin; отдельный порт даёт ей полноценную среду, но отрезает от API просмотрщика |
| Автозапуск через launchd (LaunchAgent) | Сервер должен подниматься сам после перезагрузки и возвращаться после падения, без терминала |

## 3. Общая схема

```
             ┌──────────────── браузер ───────────────┐
             │ public/index.html + app.js + styles.css│
             │  дерево · меню · документ · поиск      │
             └───┬──────────────────────────┬─────────┘
       fetch /api/…                    EventSource /api/events
                 │                          │
      ┌──────────▼──────────────────────────▼──────────┐
      │  server.mjs  (127.0.0.1:4179)                  │
      │  дерево+кеш · конфиг · поиск · open · SSE      │
      │  ┌───────────────────────────────────────────┐ │
      │  │ fs.watch(recursive) по каждому проекту    │ │
      │  └───────────────────────────────────────────┘ │
      └───┬───────────────────────────────┬────────────┘
          │ чтение файлов                 │ spawn('open', …)
   ┌──────▼──────┐  ┌──────▼──────┐   ┌───▼────────────────┐
   │ Репозиторий │  │ Репозиторий │…  │ VS Code · Cursor · │
   │   CMK-PM    │  │    AF-PM    │   │ Obsidian · Finder  │
   └─────────────┘  └─────────────┘   └────────────────────┘

      второй сервер на случайном порту — только /raw/<project>/<путь>:
      отдельный origin для встроенных HTML-страниц
```

## 4. Сервер (`server.mjs`)

### Проекты

`loadProjects()` собирает список корней по убыванию приоритета: аргументы командной строки →
`DOCVIEWER_ROOTS` (через `:`) → `DOCVIEWER_ROOT` → `projects.json` рядом с сервером → текущая папка.
Несуществующие пути пропускаются с сообщением в журнал. У каждого проекта есть `id` (slug имени),
`name` и абсолютный `root`; `id` попадает в адрес страницы и в каждый запрос к API.

### Безопасность путей

`safeAbs(root, rel)` разворачивает относительный путь и проверяет, что результат лежит внутри корня
проекта; иначе — ошибка. Через эту функцию проходит **любое** обращение к файлу, включая `/raw/`.
Сервер слушает только `127.0.0.1`.

### Дерево

`buildTree()` рекурсивно обходит корень, пропуская служебное: `SKIP_DIRS` (`.git`, `node_modules`,
`.venv`, `__pycache__`, `vendor`, …) и `SKIP_REL` — полные относительные пути вроде
`.claude/worktrees` и `.claude/projects` (рабочие копии агентов). Результат кешируется по `id`
проекта (`treeCache`) и сбрасывается при любом событии файловой системы.

### Названия документов

`docTitle()` читает первые 8 КБ файла и берёт название из frontmatter (`title` или `export_title`),
иначе из первого заголовка `# …`, иначе возвращает пусто — и тогда клиент показывает имя файла.
Кеш по `mtime`: перечитывается только изменённый файл.

### Конфигурация меню

`readConfig()` читает `docviewer.json` из корня проекта и приводит к виду
`{title, subtitle, sections, hidden, favorites, source, notice}`. Если файла нет или он не разобран,
возвращаются папки верхнего уровня, а причина кладётся в поле `notice` — **не** `error`: клиент
трактует `error` в любом ответе как сбой запроса.

`writeConfig(project, paths)` принимает от клиента порядок и состав разделов. Разделы, которых нет
в списке, не удаляются, а сохраняются с `"hidden": true` — их подпись, значок и описание вернутся
вместе с разделом. `writeFavorite(project, rel, on)` правит массив `favorites` в том же файле.

### Папки, с которыми работали

Экран выбора проекта не хранит свой список — он собирается из того, что приложения уже держат у себя:

| Источник | Где лежит | Что берём |
|----------|-----------|-----------|
| Claude Code | `~/.claude.json`, ключи `projects` | путь; дату — по mtime папки сессий `~/.claude/projects/<slug>` |
| Cursor | `~/Library/Application Support/Cursor/User/workspaceStorage/*/workspace.json` | `folder` как `file://`-адрес; дату — по mtime папки |
| VS Code | то же в `.../Code/User/workspaceStorage` | то же |
| ChatGPT · Codex | `~/.codex/sessions/**/*.jsonl` | `cwd` из первой строки сессии (читаем первые 4 КБ); дату — по mtime файла |

Пути, которых уже нет на диске, отбрасываются; корень диска и домашняя папка не считаются проектом.
Результат кешируется на 20 секунд. Локальные добавления и убранное в подвал лежат в `workspaces.json`
рядом с сервером (в `.gitignore`), а звёздочка правит `projects.json`: `fav: false` означает, что
проект открывается по ссылке, но в списке наверху не показывается. Список проектов перечитывается
на лету — новая папка сразу получает наблюдателя за файлами, а вкладки узнают об изменении из SSE.

Выбор папки вручную делает системный диалог (`osascript … choose folder`): у браузера своего выбора
папки нет, а путь нам нужен настоящий.

### Поиск

`search()` идёт по плоскому списку текстовых файлов дерева, ищет подстроку в пути и в содержимом,
отдаёт до четырёх строк-совпадений на файл. Сортировка: сначала неархивные (`Archive/`, `_archive/`
уходят в конец), затем совпадения по имени, затем по числу совпадений, затем по алфавиту.

### Живое обновление

`fs.watch(root, { recursive: true })` на каждый проект. События фильтруются теми же правилами, что и
дерево, копятся 120 мс (`pending` + `timers`), после чего сбрасывается кеш дерева и всем SSE-клиентам
уходит `{type:'change', project, paths, at}`. Клиент перечитывает дерево, при изменении `docviewer.json`
— конфигурацию, а при изменении открытого документа перерисовывает его, сохраняя позицию прокрутки.
Если открыта папка, перерисовывается её список — при появлении или удалении файла внутри неё.

### Открытие в приложениях

`/api/open` запускает `open`: `-a Obsidian`, `-R` (показать в Finder) или без аргументов —
приложение по умолчанию. Список приложений закрытый: произвольная команда снаружи не задаётся.

Отдельные случаи — редакторы и Claude Code.

**VS Code и Cursor** открываются не через `open`, а своей же командой из бандла
(`Contents/Resources/app/bin/code` и `…/bin/cursor`): `cli <корень репозитория> <файл>`. Тогда
рабочей папкой окна становится проект, а документ открывается внутри него; `open -a` вместо этого
подкидывает файл в последнее активное окно с чужой рабочей папкой. Команду из бандла ищем раньше
одноимённой в `PATH`: в `PATH` может лежать чужая обёртка (на этой машине `~/.local/bin/cursor` —
шим агента, редактор он не открывает). Команды нет — остаётся прежний `open -a`.

Cursor вдобавок получает `-n`. Без него папка уходит последнему активному окну, и если это окно с
несколькими корнями (например, «Cursor Agents»), она молча добавляется туда как ещё один корень, а
файл открывается в чужом проекте — именно так выглядела «Cursor открывает файл, но не ту папку».
С `-n` он открывает окно на нужном проекте, а при следующих кликах переиспользует это же окно, так
что окна не плодятся (проверено: после трёх открытий окон по-прежнему одно). VS Code делает это
сам, и `-n` ему только плодило бы окна, поэтому флаг задан per-app в `EDITOR_FLAGS`.

**Новый чат Claude Code** открывается ссылкой приложения:

```
claude://code/new?folder=<корень>&q=@<путь документа от корня>&source=external
```

Это тот же путь, которым пользуется пункт Finder «New Claude Code Session Here». Папка передаётся
ровно одна — корень репозитория (CLAUDE.md, git, весь проект). Вторую, папку документа, пришлось
убрать: с двумя `folder` сессия начиналась не с корня, а из меню, где папка была одна, всё
работало — отсюда и разница в поведении. На экране меню кнопка активна и открывает сессию в корне.

Важная деталь: обработчик `/code/new` читает `file`, но **не пробрасывает** его дальше — в раздел
Code уходят только `folder` (все) и `q`/`prompt`. Поэтому сам документ называем через `q`:
поле ввода новой сессии открывается с `@<путь от корня репозитория>`, а Claude Code такие
@-упоминания понимает. Параметр `file` работает у другой ссылки — `claude://cowork/new`, но она
открывает не Code, а раздел задач.

Каждый запуск пишется в журнал строкой «открываю: …» — чтобы было видно, чем именно кончился клик,
если приложение «ничего не сделало».

### Значки приложений

`/api/appicon?app=…` отдаёт настоящий значок установленного приложения: из бандла читается
`CFBundleIconFile` (а если plist двоичный — берётся самый крупный `.icns` в `Resources`),
`sips` конвертирует его в png 64×64, результат кешируется в `$TMPDIR/docviewer-icons`.
Параллельные запросы к одному приложению разделяют одну конвертацию (`iconJobs`).
Приложения нет — 404, и на кнопке остаётся текстовая подпись. Брендовые картинки в репозитории
не хранятся: интерфейс показывает то, что уже установлено в системе.

### Два сервера

Основной сервер отдаёт интерфейс и API. Второй (`assetServer`, порт `0` — случайный свободный)
знает единственный маршрут `/raw/<project>/<путь>` и нужен для встроенных HTML-страниц: у них
свой origin, поэтому скрипты и `localStorage` работают, а до API просмотрщика они не достают.
Его адрес клиент получает в `/api/meta` полем `assets`. Дополнительно все POST с чужим origin
отклоняются с кодом 403.

## 5. HTTP API

Все маршруты принимают `?project=<id>`; без него берётся первый проект списка.

| Маршрут | Метод | Назначение |
|---------|-------|------------|
| `/api/projects` | GET | Список подключённых репозиториев |
| `/api/meta` | GET | Имя и корень текущего проекта, origin сервера страниц, список проектов |
| `/api/tree` | GET | Полное дерево файлов (из кеша) |
| `/api/appicon?app=` | GET | Значок установленного приложения в png; 404, если приложения нет |
| `/api/config` | GET | Разделы меню, скрытые разделы, избранное, источник и пояснение |
| `/api/config` | POST | `{sections: [путь, …]}` — сохранить состав и порядок меню |
| `/api/favorite` | POST | `{path, on}` — добавить или убрать документ из избранного |
| `/api/dir?p=` | GET | Содержимое папки: вложенные папки со счётчиками и документы с названиями |
| `/api/file?p=` | GET | Текст файла либо пометка `binary: true` с размером и расширением |
| `/raw?p=` | GET | Файл как есть (картинки, PDF, исходник страницы) |
| `/raw/<project>/<путь>` | GET | То же, но «настоящим» путём — чтобы относительные ссылки внутри HTML работали |
| `/api/search?q=` | GET | Поиск по именам и содержимому (от двух символов) |
| `/api/open` | POST | `{path, app}` — открыть файл в нативном приложении; `app: 'claude'` открывает новый чат Claude Code в папке |
| `/api/events` | GET | Поток SSE об изменениях на диске |

Ошибки отдаются как `{error: "…"}` с кодом 400 или 403.

## 6. Клиент (`public/app.js`)

Один модуль в IIFE, без сборки. Состояние — объект `state`: дерево и его индексы, текущий документ,
разделы меню, избранное, список проектов, режим настройки, origin сервера страниц. Проект берётся
из `?project=`, адрес документа — из хеша (`#design/screens/DOC.md`), поэтому ссылку можно сохранить
в закладки и работают «назад»/«вперёд». В `localStorage` (ключи с префиксом `dv.<project>.`) лежат
раскрытые ветки дерева и ширина боковой панели — у каждого проекта своё.

| Блок | Функции |
|------|---------|
| Меню и настройка | `renderHome`, `saveSections`, `hideSection`, `showSection`, `toggleFavorite`, `syncFavButton` |
| Навигация по папкам | `openDir`, `folderTile`, `fileTile`, `renderCrumbs`, `navigate`, `openPath` |
| Документ | `openFile`, `enhance`, `renderFrontmatter`, `renderPage`, `pageBar` |
| Дерево | `renderTree`, `loadTree`, `revealInTree`, `matchesFilter` |
| Таблицы | `textWidth`, `widestText`, `cellDemand`, `columnDemand`, `layoutTable`, `relayoutTables` |
| Схемы | `initMermaid`, `decorateDiagram`, `openZoom`, `fitZoom`, `applyZoom`, `bindZoom` |
| Поиск | `runSearch` (по репозиторию), `runFind` / `focusHit` / `clearMarks` (внутри документа), палитра `⌘P` |
| Оболочка | `bindSidebarControls`, `connectEvents`, `renderProjectSwitch`, `bindUI`, `boot` |

Кнопка «⧉» кладёт в буфер полный путь: корень проекта клиент знает из `/api/meta`, внутри же
приложения всё адресуется путями от корня репозитория.

Рендер идёт в одну сторону: любое действие меняет хеш адреса, а перерисовку делает обработчик
`hashchange` — так исключается двойной рендер одного и того же состояния.

**Позиция прокрутки живёт в записи истории.** Перед сменой адреса `saveScrollNow` кладёт текущую
позицию в `history.state` (плюс отложенная запись при обычной прокрутке), а обработчик `hashchange`
читает `history.state.scroll` той записи, куда мы попали, и передаёт её в отрисовку. Свежая запись
состояния не имеет, поэтому документ открывается сверху, а «назад» и «вперёд» возвращают туда, где
вы стояли. Позиция применяется после отрисовки и повторяется несколько раз с задержкой: схемы и
таблицы меняют высоту страницы уже после вставки разметки. `requestAnimationFrame` для этого не
годится — в фоновой вкладке он не срабатывает.

**Файл, который интерфейс показать не может, не заменяет страницу.** Решение принимается в
`openFile` уже после ответа сервера (`data.binary` и расширение), то есть на всех маршрутах сразу:
плитка, дерево, ссылка в документе, палитра, закладка, «назад» и «вперёд». Состояние при этом не
трогается, а `keepView` возвращает адрес на прежнее место через `history.replaceState` — без
`hashchange`, значит и без перерисовки. Быстрая проверка в `navigate` осталась: она экономит
лишний запрос, когда файл уже известен из дерева.

## 7. Алгоритмы, которые стоит знать

### Ширина колонок таблицы

Эвристика перенесена из `scripts/fix_docx_tables.py` (подготовка таблиц к выгрузке в DOCX), чтобы
таблицы выглядели одинаково на экране и в Word. Порядок:

1. **Минимум колонки** — самый длинный кусок, который браузер не разорвёт. Ширина меряется
   настоящим шрифтом ячейки через `canvas.measureText`, а не средней шириной символа. Перенос
   браузер делает только после дефиса, поэтому `CHK/DMS` считается неделимым.
2. **Шрифт `кода` учитывается отдельно**: он задан в пикселях и не уменьшается вместе с таблицей,
   поэтому его требование (плюс отступы) не масштабируется.
3. **Спрос колонки** по объёму текста: `(√средняя_длина · 9 + √максимальная · 5) · (1 + 0,3 · длинные_ячейки)`.
4. Ширины раздаются пропорционально спросу, затем **жёстко поднимаются до минимумов**; излишек
   срезается только с запаса над минимумом — поэтому слова не рвутся.
5. Если минимумы не влезают, шрифт таблицы уменьшается 13 → 12 → 11 px, и только если не помогло —
   таблица становится шире колонки и прокручивается вбок.

Пересчёт вызывается при изменении ширины области текста (`ResizeObserver` на `#doc` плюс `resize`).

### Номера строк документа

`marked.lexer` разбирает текст на верхнеуровневые блоки и хранит у каждого исходный кусок
(`token.raw`) — по числу переводов строки в нём и считается, с какой строки файла блок начинается.
Каждый блок разбирается отдельно (`marked.parser([token])`, с перенесённым `tokens.links`, иначе
потеряются ссылки-сноски), номер кладётся в `data-line`, а рисуется псевдоэлементом в поле слева:
сама разметка документа не меняется. Отсчёт учитывает YAML-заголовок — `splitFrontmatter` отдаёт,
сколько строк ушло на него. Если разбор по блокам не удался, документ рисуется как раньше, просто
без номеров.

Блоки с собственной горизонтальной прокруткой — таблицы, код, схемы — срезали бы номер по своему
краю, поэтому для них номер переезжает на внешнюю обёртку `.lined-block`.

Строки таблиц и пункты списков нумеруются каждый своим номером. Для таблицы это прямой счёт по
исходному куску (в markdown строка таблицы — ровно одна строка файла: шапка, разделитель, дальше
по строке на запись), для списков — обход `token.items` с учётом того, что пункт может занимать
несколько строк; вложенные списки обходятся рекурсивно. Псевдоэлемент здесь не годится: у строк и
пунктов разная высота, а поле с номерами лежит вне прокручиваемой обёртки — поэтому
`placeMeasuredNumbers` расставляет их по измеренным позициям после раскладки и повторяет это при
каждом пересчёте ширины. Пересчёт слушает размер `#doc`, а не всей страницы: при сворачивании
боковой панели окно не меняется, а колонка текста — меняется.

### Номера строк у кода

Номера рисуются отдельной колонкой рядом с `pre`, а не вставляются в сам код: разметку подсветки
`highlight.js` трогать нельзя — теги там перекрывают границы строк, и разрезание по `\n` их ломает.
Колонка лежит вне прокручиваемого `pre`, поэтому при горизонтальной прокрутке кода номера стоят на
месте, а `user-select: none` не пускает их в буфер обмена. Совпадение строк держится на одинаковых
кегле, межстрочном интервале и верхнем отступе у колонки и у кода. Блоки короче трёх строк
не нумеруются, файл, открытый целиком, — всегда.

### Поиск внутри документа

`runFind` обходит текстовые узлы документа (`TreeWalker`), пропуская содержимое схем (`svg`),
и оборачивает совпадения в `<mark class="find-hit">`. Перед новым поиском `clearMarks()` снимает **обе** подсветки
(`find-hit` и `q-hit` от поиска по репозиторию) и склеивает текстовые узлы: иначе разметка от
прошлой подсветки разрезает текст и поиск сообщает «нет совпадений» поверх подсвеченного слова.

### Схемы Mermaid

Рисуются в натуральную величину, широкая схема прокручивается вбок. Полноэкранный просмотр —
собственный масштаб и перетаскивание (`fitZoom` считает масштаб «по ширине», `applyZoom` применяет
`transform`), потому что встроенный зум Mermaid не даёт нужной точности.

## 8. Эксплуатация

| Задача | Команда |
|--------|---------|
| Ручной запуск | `bash ~/Git/docviewer/start.sh` |
| Автозапуск (LaunchAgent `digital.belkin.docviewer`) | `bash ~/Git/docviewer/install-agent.sh` |
| Снять автозапуск и остановить | `bash ~/Git/docviewer/install-agent.sh --uninstall` |
| Перезапуск после правки кода | `launchctl kickstart -k gui/$UID/digital.belkin.docviewer` |
| Журнал | `~/Library/Logs/docviewer.log` |

LaunchAgent поднимает сервер при входе в систему (`RunAtLoad`) и возвращает его после падения
(`KeepAlive`), браузер при этом не открывает (`DOCVIEWER_NO_OPEN=1`). Путь к `node` подставляется
тот, что найден в `PATH` при установке.

Адрес — `http://127.0.0.1:4179/`. Если порт занят, сервер берёт следующий свободный (до 20 попыток)
и печатает адрес в журнал. Частая причина «правка кода не видна» — несколько запущенных копий
сервера на соседних портах: `pkill -f "node server.mjs"` и перезапуск.

Добавить репозиторий: дописать его в `projects.json` (образец — `projects.example.json`) и
перезапустить сервер. Настроить меню проекта: кнопка «Настроить» на странице или правка
`docviewer.json` руками — перезапуск не нужен, изменения подхватываются наблюдателем.

## 9. Ограничения

- Только macOS: открытие в приложениях построено на `open`, автозапуск — на launchd.
- `fs.watch` с `recursive: true` надёжно работает на macOS и Windows; на Linux потребуется опрос.
- Поиск по содержимому читает файлы на каждый запрос, без индекса: на деревьях порядка тысяч
  документов это доли секунды, на десятках тысяч потребуется индекс.
- Дерево держится в памяти целиком и пересобирается после любого изменения в проекте.
- Нет аутентификации: защита в том, что сервер слушает только петлевой интерфейс.
