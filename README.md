# Просмотрщик документации

Локальное веб-приложение для навигации по репозиторию: дерево файлов, чтение markdown,
переходы по внутренним ссылкам, поиск и открытие файла в VS Code, Cursor, Obsidian или Finder.
Работает без интернета и без установки пакетов — только Node (проверено на 25.x).

## Запуск

```bash
bash ~/Git/docviewer/start.sh
```

Адрес: <http://127.0.0.1:4179/> (если порт занят — берётся следующий свободный, адрес печатается в консоль).
Браузер открывается сам; остановка — `Ctrl+C`.

Первый запуск скачивает три библиотеки разметки в `vendor/` (marked, mermaid, highlight.js).
Дальше интернет не нужен; папка `vendor/` не версионируется.

Переменные окружения: `DOCVIEWER_PORT` (порт), `DOCVIEWER_ROOTS` (пути проектов через `:`),
`DOCVIEWER_ROOT` (один проект), `DOCVIEWER_NO_OPEN=1` (не открывать браузер).

## Автозапуск

Чтобы сервер поднимался сам при входе в систему и возвращался после сбоя:

```bash
bash ~/Git/docviewer/install-agent.sh
```

Ставится LaunchAgent `digital.belkin.docviewer`, журнал — `~/Library/Logs/docviewer.log`,
браузер при автозапуске не открывается. Перезапуск после правки кода:

```bash
launchctl kickstart -k gui/$UID/digital.belkin.docviewer
```

Снять автозапуск и остановить сервер: `bash ~/Git/docviewer/install-agent.sh --uninstall`.

## Что умеет

| Возможность | Как работает |
|-------------|--------------|
| Несколько проектов | Список репозиториев в [`projects.json`](projects.example.json); переключатель в шапке. У каждого проекта своё дерево, свои разделы меню и своё запомненное состояние |
| Выбор проекта | Кнопка со значком плитки слева в шапке открывает экран со всеми папками, с которыми вы работали (повторное нажатие закрывает его и возвращает туда, откуда вы пришли; на самом экране вся правая часть шапки убирается): список берётся из проектов Claude Code и Codex и рабочих папок Cursor и VS Code, на плашке видно значки приложений, где папка встречалась. Звёздочка добавляет папку в список наверху, «Настроить» позволяет менять описания и убирать лишние в подвал, «＋ Добавить папку» открывает системный выбор папки — добавленную вручную можно не только убрать в подвал, но и удалить совсем. Есть поиск по имени, пути и описанию (`Enter` открывает первую найденную папку), фильтр «★ Избранные» и общий переключатель порядка; дата берётся из тех же источников и подписана на плашке |
| Название и описание проекта | «Настроить» → название и описание → «Сохранить» работает на главной и в списке проектов, включая обнаруженные и скрытые папки. `title` (до 200 символов) и единое `description` (до 2000) хранятся в корневом `docviewer.json`. Название одинаково в заголовке, форме, плашках, переключателе и боковой панели. Если оно отличается от имени папки, на главной папка подписана под заголовком; в карточке она видна только в пути. Другие открытые окна подхватывают изменения, сохраняя незавершённый ввод |
| Каталог для AI через MCP | Автономный локальный stdio-сервер: поиск по имени, пути и описанию. По умолчанию читает только избранные проекты; `scope: "all"` расширяет поиск до Cursor, VS Code, Claude Code и Codex |
| Переход по пути | Кнопка со стрелкой в шапке берёт путь из буфера обмена и сразу открывает документ; поле для ручного ввода появляется, только если в буфере не путь, файла нет или он вне проектов (тогда причина написана прямо в окне, а путь уже подставлен). Браузер спросит разрешение на чтение буфера один раз — без него кнопка просто всегда спрашивает путь. Проект подбирается сам: сначала среди избранных, потом среди не убранных в подвал, затем среди всех; если подходит несколько корней — берётся ближайший к файлу. Если корня нет, ответ короткий: «Файл вне проекта» |
| Порядок списков | Переключатель «По имени · По дате» есть в меню разделов, на экране папки и в выборе проекта. В меню к нему добавлен третий вариант «Как настроено» — порядок из `docviewer.json`, он же по умолчанию; в папке по умолчанию идёт имя, в выборе проекта — дата. Выбор запоминается и действует во всех видах |
| Меню разделов | Стартовый экран с крупными плашками по ключевым папкам: описание, число документов и все подпапки отдельными кнопками. Состав и порядок задаёт `docviewer.json` в корне открытого репозитория |
| Избранное | Кнопка «☆ В избранное» в шапке открытого документа: файл попадает в отдельный блок над разделами меню. Повторный клик («★ В избранном») убирает; в режиме настройки клик по плашке избранного тоже убирает её. Список хранится в `docviewer.json` проекта, полем `favorites` |
| Настройка меню | Кнопка «Настроить» рядом с заголовком: в этом режиме клик по разделу убирает его вниз, клик по папке внизу поднимает в меню. Каждое действие сразу пишется в `docviewer.json` проекта |
| Подвал меню | Под плашками — строка «Остальные папки»: убранные разделы (со своими подписями) и всё прочее, что лежит в корне проекта. Вне режима настройки клик по такой папке просто открывает её |
| Файлы в корне | Под «Остальными папками» — плашки файлов корневой папки. В режиме «Настроить» клик переносит файл в компактную строку «Остальные файлы», клик в этой строке возвращает плашку. В обычном режиме компактные кнопки открывают файлы. Состав блоков сохраняется в `docviewer.json` |
| Вход в папку | Классический экран папки: кнопка «↑ Наверх» (из раздела — в меню), крупные плашки вложенных папок, ниже плашки документов. Все названия с заглавной буквы |
| Плашка документа | Первая строка крупно — `title` из frontmatter, иначе первый заголовок `# …`, иначе имя файла (тогда второй строки нет). Вторая строка серым — имя файла, расширение отдельной пометкой рядом |
| Возврат из документа | Кнопка «↑ Имя папки» в шапке открывает папку, из которой документ был открыт |
| Боковая панель | Всё дерево репо, кроме служебного (`.git`, `node_modules`, `__pycache__`, `.claude/worktrees`). Раскрытые ветки запоминаются. Сворачивается кнопкой «‹» или `⌘B`, разворачивается значком панели у самого левого края шапки, ширина меняется перетаскиванием границы (двойной клик по границе — сброс к 320 px) |
| Markdown | Таблицы, цитаты-выноски, код с подсветкой, схемы Mermaid, YAML-заголовок отдельным блоком, оглавление справа |
| Номера строк | У каждого блока документа — заголовка, абзаца, таблицы, схемы, вставки кода — слева стоит неяркий номер строки в файле; у таблиц и списков номер стоит у каждой строки и каждого пункта, включая вложенные: по нему видно, куда смотреть в исходнике и что цитировать. Отдельно нумеруются строки внутри блоков кода и файлов, открытых целиком (вставки короче трёх строк — без нумерации). В выделение и буфер номера не попадают |
| Ширина колонок таблиц | Считается по содержимому: спрос колонки по объёму текста плюс нижняя граница по самому длинному неразрывному слову (та же эвристика, что в скрипте подготовки таблиц для экспорта в DOCX). Слово целиком не разрывается: колонка обязана его вместить (в расчёте учитываются шрифт `кода`, его отступы и то, что браузер переносит только после дефиса). Если минимумы не вмещаются, шрифт таблицы уменьшается до 12, затем до 11 px, и лишь потом включается боковая прокрутка. Пересчитывается при изменении ширины панели или окна |
| Схемы Mermaid | Рисуются в натуральную величину (не ужимаются до нечитаемости): широкая схема прокручивается вбок, кнопка «⤢ Во весь экран» или двойной клик открывает её поверх страницы с масштабом (`+`, `−`, «По ширине», «1:1», `⌘`+колесо) и перетаскиванием мышью |
| Поиск в документе | `⌘F` — панель поиска по открытому документу: подсветка всех совпадений, счётчик «3 из 12», переходы `Enter` / `⇧Enter` или `⌘G`, `Esc` — закрыть |
| Возврат «назад» | Браузерная кнопка «назад» (а также `⌘[` и свайп) возвращает документ на то место, с которого вы ушли по ссылке — позиция хранится в самой записи истории, поэтому работает на любую глубину и в обе стороны. Документ, открытый впервые, показывается сверху |
| Внутренние ссылки | Относительные ссылки (`../comms/meetings/…`) открываются внутри приложения; ссылки на папки — списком; несуществующие цели зачёркнуты. Ссылки на заголовки работают и внутри документа (`#название-раздела`), и в другой документ (`file.md#раздел`); адрес в строке браузера меняется, поэтому такую ссылку можно скопировать, а «назад» вернёт на прежнее место. Если заголовка нет, об этом скажет всплывающая подсказка |
| Картинки и PDF | Показываются на странице |
| HTML-файлы | Открываются готовой страницей, а не исходником: со стилями, скриптами и рабочими относительными ссылками. Кнопки над ней — «↗ В новой вкладке» и «⟨⟩ Исходный код» (обратно — «▦ Страница»). Страницы отдаёт отдельный локальный порт, поэтому у них свой origin: они работают полноценно, но к данным просмотрщика доступа не имеют |
| Прочие двоичные файлы | `.docx`, `.xlsx`, архивы и всё, что интерфейс показать не может, по клику сразу открываются в приложении по умолчанию. Открытая страница при этом не меняется — откуда бы ни пришёл переход: плитка, дерево, ссылка в документе, закладка или «назад» в браузере |
| Поиск | По имени и по содержимому всех текстовых файлов; совпадения подсвечиваются в открытом документе, архив — в конце списка |
| Быстрое открытие | `⌘P` или `⌘K` — поиск файла по части пути |
| Горячие клавиши | `⌘P`/`⌘K` — быстрое открытие, `⌘F` — поиск в документе, `⌘G` — следующее совпадение, `⌘B` — свернуть панель, `Esc` — закрыть панель поиска, палитру или просмотр схемы |
| Открыть в приложении | Компактные кнопки-значки справа в шапке: Visual Studio Code, Cursor, Obsidian, Claude Code, Codex, Finder, «☆» (избранное) и «⧉» (скопировать полный путь к файлу). Значки берутся у самих приложений — если приложения в системе нет, на кнопке остаётся короткая подпись. На плашке документа тоже есть «⧉»: копирует путь, не открывая файл |
| Редакторы | VS Code и Cursor запускаются своей же командой из бандла приложения: рабочей папкой окна становится корень репозитория, а документ открывается внутри него. Cursor получает дополнительно `-n`, иначе он добавляет папку в последнее активное окно вместо того, чтобы открыть проект. Если команду найти не удалось, файл открывается через `open -a`, как раньше |
| Новый чат Claude Code | Кнопка со значком Claude открывает в приложении Claude новую сессию раздела Code — ссылкой `claude://code/new`, той же, что у пункта Finder «New Claude Code Session Here». Папка передаётся одна — корень репозитория (от второй, папки документа, сессия начиналась не с корня), а сам документ подставляется в поле ввода @-упоминанием (`@testing/README.md`) — ссылка иначе его не передаёт. Папку из внешней ссылки приложение корнем молча не делает: оно спрашивает доверие к ней, и после ответа папка становится корнем сессии. Кнопка работает и на экране меню: там сессия открывается в корне проекта |
| Новый чат Codex | Кнопка со значком Codex открывает в приложении ChatGPT новую сессию Codex — ссылкой `codex://threads/new`. Правила те же: рабочей папкой чата становится корень репозитория, документ подставляется в поле ввода @-упоминанием. Если проекта с таким корнем у Codex ещё не было, он заводит его сам. Кнопка работает и на экране меню |
| Живое обновление | `fs.watch` по каждому подключённому репозиторию + SSE: правка файла на диске сразу перерисовывает открытый документ (позиция прокрутки сохраняется), появление и удаление файлов обновляет дерево и список открытой папки |

Вернуться в меню — кнопка с домиком слева в шапке или клик по имени репозитория; кнопка рядом с ней
(«↑ Имя папки») поднимает на уровень выше — к папке открытого документа.

## Разделы меню: `docviewer.json`

Файл лежит в корне **каждого репозитория** и правится вручную — приложение подхватывает изменения
сразу, перезапуск не нужен. Если файла нет, меню показывает все папки верхнего уровня проекта,
о чём пишет строкой под заголовком.

```json
{
  "title": "Навигация по документации",
  "description": "Назначение проекта и что здесь можно найти — для списка проектов и MCP",
  "sections": [
    { "path": "design", "title": "Дизайн", "icon": "◧", "description": "Экраны, доменная модель, Gherkin" }
  ]
}
```

`title` задаёт отображаемое название проекта. Если он отсутствует, пуст или равен старому общему
заголовку «Навигация по документации», сервер возвращает имя из локального списка проектов,
а для обнаруженных папок — имя папки. Это правило одинаково для всех экранов, форм и MCP.
Имя папки под заголовком вычисляется из полного пути, отдельно в настройках не хранится.
`description` — единственное описание для
домашней страницы, списка проектов и MCP. Старое `subtitle` используется как описание только
при отсутствии `description`; при следующем сохранении оно заменяется на `description`.
Если оба поля есть, сохраняется `description`. Пустое описание тоже можно сохранить.

| Поле | Смысл |
|------|-------|
| `path` | Папка от корня репо. Обязательное. Если папки нет — плашка показана серой с пометкой |
| `title` | Подпись на плашке; по умолчанию — имя папки |
| `icon` | Значок, любой символ или эмодзи |
| `description` | Строка под заголовком плашки |

Избранные файлы хранятся в том же файле массивом путей:

```json
{ "favorites": ["SSOT/documentation-guide.md", "plan/scope/Scope_005_ai-platform-development.md"] }
```

Файлы, скрытые из блока «Файлы в корне», хранятся массивом имён `"hiddenFiles": ["package-lock.json", "docviewer.json"]`.
Они отображаются компактными кнопками в строке «Остальные файлы» и остаются доступны в дереве, поиске и избранном. Без этого поля все файлы корня показаны плашками.

Разделы, убранные из меню кнопкой «Настроить», остаются в файле с пометкой `"hidden": true` —
их подпись, значок и описание сохраняются и возвращаются вместе с разделом (он встаёт в конец меню).
Порядок разделов в файле определяет порядок плашек. Короткая запись `"sections": ["design", "comms"]`
тоже допустима. Если в файле ошибка разбора, приложение показывает папки верхнего уровня и пишет
причину на экране меню.

Адрес документа хранится в хеше URL (`…/#design/screens/DOC_CHK_008_check-run.md`) — ссылку можно
сохранить в закладки, работают «назад» и «вперёд» в браузере.

| [`install-agent.sh`](install-agent.sh) | Ставит или снимает автозапуск через launchd |
| [`projects.json`](projects.example.json) | Список репозиториев этой машины (локальный, в `.gitignore`) |
| `docviewer.json` | Разделы меню — лежит в корне каждого репозитория и версионируется вместе с ним |

Сервер слушает только `127.0.0.1` и отдаёт файлы исключительно из корней подключённых проектов
(пути за их пределы отклоняются). Встроенные HTML-страницы обслуживает второй сервер на случайном
локальном порту — у них отдельный origin, а запросы к API с чужого origin отклоняются. Настройки
меню, избранное и описание записываются в `docviewer.json` проекта; каталог машины — в локальные
`projects.json` и `workspaces.json`.

## Локальный MCP: каталог проектов

`node ~/Git/docviewer/mcp-server.mjs` запускает отдельный сервер по
[стандартному stdio-транспорту MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio).
Он работает без веб-сервера, браузера, сети и дополнительных пакетов; читает только метаданные
проектов и их `docviewer.json`, без обхода содержимого репозиториев. Поддерживает MCP 2025-11-25,
2025-06-18, 2025-03-26 и 2024-11-05.

Подключение к Codex ([официальная инструкция](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)):

```bash
codex mcp add docviewer-projects -- "$(command -v node)" "$HOME/Git/docviewer/mcp-server.mjs"
codex mcp get docviewer-projects
```

Для другого MCP-клиента укажите stdio, полный путь к Node в `command` и полный путь к
`mcp-server.mjs` в `args`. Рабочая папка не важна: каталог берётся рядом с сервером.

| Инструмент | Параметры | Результат |
|------------|-----------|-----------|
| `list_projects` | `query?`, `scope?: "starred" / "all"`, `include_hidden?: false`, `limit?: 30` (1–100), `offset?: 0` | `projects`, `total`, `nextOffset`; поиск по словам в имени, заголовке, абсолютном пути и описании |
| `get_project` | `path` — абсолютный путь или `~/…` из каталога | `project` с актуальным описанием |

Первый круг — `list_projects` без параметров или с `query`: это только starred из `projects.json`
и их настройки, без чтения историй редакторов. Если нужного проекта нет, вызовите тот же инструмент
с `scope: "all"`. В полном каталоге starred идут первыми, скрытые папки добавляются только с
`include_hidden: true`. `get_project` также проверяет избранные перед историей приложений.
Каждый проект содержит `name`, `title`, `path`, `description`, `starred`, `hidden`, `sources`, `lastUsedAt`
и `settingsFile`. В первом круге источники и дата из истории не загружаются (`[]` и `null`).
Истории приложений кешируются на 20 секунд; звёздочки и описания перечитываются на каждый вызов.
Описание — данные проекта; MCP не исполняет содержащиеся в нём инструкции и ничего не записывает.

Проверка протокола, поиска, открытия проектов и сохранности настроек: `node --test`.
